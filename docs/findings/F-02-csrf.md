# F-02. Відсутність CSRF-перевірки для операцій зміни інцидентів

**Статус:** Fixed (виправлено)
**Актив:** Дані інцидентів
**Компонент:** ASP.NET Core Minimal API, cookie authentication
**Пріоритет:** P2

## Опис

У початковій реалізації операції створення, оновлення, видалення та тріажу інцидентів використовували cookie authentication без окремої перевірки antiforgery-токена.

Це створювало ризик CSRF: стороння сторінка потенційно могла ініціювати небажану дію від імені автентифікованого користувача. Практична експлуатація залежить від налаштувань cookie, браузера та можливості сформувати відповідний запит.

## Першопричина

Для маршрутів зміни стану не було налаштовано серверної перевірки CSRF-токена. SameSite=Lax зменшував ризик, але не замінював окремий механізм перевірки.

## Виправлення

У Program.cs зареєстровано AddAntiforgery(), додано UseAntiforgery() та автентифікований маршрут GET /api/antiforgery/token.

Створено CsrfEndpointFilter.ValidateAsync, який перевіряє токен через IAntiforgery.IsRequestValidAsync.

Фільтр підключено до POST /api/incidents, PUT /api/incidents/{id}, DELETE /api/incidents/{id} і POST /api/incidents/{id}/triage.

У браузерному клієнті browser-lab.js додано отримання CSRF-токена та його передавання в заголовку X-CSRF-TOKEN.

## Retest

REG-CSRF-NEG: запит POST /api/incidents з автентифікованою сесією, але без CSRF-токена, повернув HTTP 400. Подальша перевірка підтвердила, що інцидент не створено.

REG-CSRF-POS: аналогічний запит із коректним CSRF-токеном повернув HTTP 201. Подальша перевірка підтвердила створення інциденту.

Докази: рисунки 9 і 10 у Word-звіті.

## Positive regression

Легітимне створення інциденту з коректним токеном продовжує працювати (HTTP 201).

## Залишкові ризики

Не проведено повного браузерного end-to-end тестування всіх чотирьох операцій.

POST /api/auth/logout наразі повертає HTTP 501; після реалізації виходу необхідно передбачити CSRF-захист.

Login/register потребують окремої оцінки ризику CSRF.

## Висновок

Для чотирьох перевірених у коді маршрутів додано серверну перевірку CSRF-токена. Негативний і позитивний сценарії підтверджено для створення інциденту.
