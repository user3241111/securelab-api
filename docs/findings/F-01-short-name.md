# F-01. Навчальні облікові дані PostgreSQL у конфігурації

**Статус:** Accepted (study-only)
**Актив:** Облікові дані локальної PostgreSQL
**Компонент:** Docker Compose, ASP.NET Core, EF Core
**Пріоритет:** P3 (низький для локального навчального середовища)

## Передумови і межі огляду

Перевірку проведено для локального навчального проєкту SecureLab API у гілці `lab/6-hardening-review`.

Review-start commit: `e554f1092c3abb451cda8ebf39af17f1e42ff60b`.

Початковий тег `v0.5.0`: `8c336b9448b85f5b0b01821a9431179c018d4d32`.

Перевірено поточні конфігураційні файли, які відстежуються Git. Повний аналіз історії Git не проводився. Продуктивні бази даних і зовнішні середовища не перевірялися.

## Відтворення

1. Переглянуто конфігурацію Docker Compose, ASP.NET Core та EF Core.
2. Виявлено однакові навчальні облікові дані PostgreSQL у трьох файлах:
   - `infra/compose.yaml`;
   - `src/SecureLab.Api/appsettings.Development.json`;
   - `src/SecureLab.Api/Data/SecureLabDesignTimeDbContextFactory.cs`.
3. Підтверджено, що файли відстежуються Git.
4. Перевірено фактичну конфігурацію Docker Compose командою `docker compose -f infra/compose.yaml config --format json`.
5. Встановлено, що сервіс `postgres` має `host_ip = 127.0.0.1`, published port `54329` і target port `5432`.

**Очікуваний результат:** навчальні credentials використовуються лише в ізольованому локальному середовищі та не застосовуються до реальних систем.

**Фактичний результат:** credentials зберігаються у трьох tracked files. Docker Compose налаштований публікувати PostgreSQL через loopback-інтерфейс.

Фактичну мережеву доступність запущеного контейнера окремо не перевірено.

## Вплив і ймовірність

**Статус перевірки:** підтверджено переглядом локального коду та конфігурації.

Значення є навмисними навчальними credentials, передбаченими baseline SecureLab. Для локального стенда їх використання допускається методичними рекомендаціями.

Потенційний ризик виникне, якщо ці credentials повторно використати в іншій базі даних, продуктивному середовищі або системі, доступній стороннім особам.

Ознак такого повторного використання не встановлено.

## Першопричина

Навчальна конфігурація SecureLab містить фіксовані облікові дані для відтворюваного запуску локального PostgreSQL.

Це свідоме рішення навчального baseline, а не підтверджений витік реального секрету.

## Виправлення

Зміни конфігурації не виконувалися.

Прийнято рішення `accepted, study-only`, оскільки методичка дозволяє ці навчальні значення за умови використання виключно в локальному середовищі.

Виносити їх у змінні середовища для виконання мінімального рівня ЛР №6 не потрібно.

## Retest

Повторно перевірено конфігурацію Docker Compose.

Фактичний результат:

- Service: `postgres`;
- Host IP: `127.0.0.1`;
- Published port: `54329`;
- Container port: `5432`.

Це підтверджує локальну прив'язку опублікованого порту в конфігурації.

## Positive regression

Оскільки конфігурацію не змінювали, окремий retest після виправлення не застосовується.

Під час попередніх інтеграційних перевірок SecureLab отримано результат 20 passed, 0 failed, 0 skipped.

Цей результат не є окремим доказом фактичної мережевої ізоляції PostgreSQL.

## Залишковий ризик

Навчальні credentials залишаються у tracked files.

Їх не можна повторно використовувати для реальних баз даних або інших середовищ.

Якщо справжній credential потрапить до Git, недостатньо просто видалити його з поточного файла: необхідно відкликати або змінити credential, оцінити історію Git та можливе поширення репозиторію.

Повний аналіз історії Git не входив до обраного достатнього рівня.

## Доказ

- Перегляд трьох конфігураційних файлів.
- `git ls-files`.
- `docker compose -f infra/compose.yaml config --format json`.
- Фактична конфігурація порту PostgreSQL: `127.0.0.1:54329 -> 5432`.

Значення пароля та повний connection string у документі навмисно не наведено.
