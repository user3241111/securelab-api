
# Звіт ЛР04

## Контекст і межа виконання

- Рівень виконання: добрий («Добре»), включно з вимогами достатнього рівня.
- Предметний сценарій: baseline 2-A, навчальний трекер інцидентів SecureLab API.
- Початковий тег: v0.3.0.
- Початковий commit: 5b5c4dc.
- Основна захищена операція: GET /api/incidents/{id}.
- Обрана політика відмови для чужого ресурсу: HTTP 403 Forbidden.
- Основний ресурс: Incident.
- Дочірній ресурс: IncidentComment.

Для рівня «Добре» передбачено перевірку списку, деталей, оновлення й видалення інцидентів, дочірнього ресурсу, привілейованого переходу стану та аудиту відмов.

Додаткові перевірки пошуку та агрегованої статистики A-11 належать до рівня «Відмінно» і не входять до обраного обсягу.

## Матриця і server-side рішення

Правила контролю доступу визначено у файлі docs/access-matrix.md.

Reporter може переглядати власні інциденти та редагувати дозволені текстові поля. Доступ до чужих інцидентів заборонено.

Analyst має право переглядати інциденти для аналізу та виконувати дозволений перехід стану New → Triaged.

Administrator не отримує автоматичного доступу до інцидентів. Права обмежуються безпосередньо визначеними предметними правилами.

Власник ресурсу повинен визначатися сервером через перевірений principal, а не з параметрів HTTP-запиту.

Для неавтентифікованих користувачів передбачено HTTP 401, для користувачів без необхідних прав — HTTP 403, а для неіснуючих ресурсів — HTTP 404.

Централізований контроль доступу та захист серверних полів реалізовано й перевірено HTTP-запитами та автоматизованими тестами.

## Вразливий стан і PoC

У початковому стані було відтворено горизонтальну вразливість IDOR/BOLA під час перегляду інцидентів.

Сценарій 1. Alice переглядає власний інцидент.

- Користувач: Alice, роль Reporter.
- Метод: GET.
- Ресурс: 20000000-0000-0000-0000-000000000001.
- Очікуваний результат: HTTP 200 OK.
- Фактичний результат: HTTP 200 OK.
- Результат: повернуто дані власного інциденту Alice.

Сценарій 2. Alice переглядає чужий інцидент Bob.

- Користувач: Alice, роль Reporter.
- Метод: GET.
- Ресурс: 20000000-0000-0000-0000-000000000002.
- Очікуваний результат: HTTP 403 Forbidden.
- Фактичний результат: HTTP 200 OK.
- Результат: повернуто назву інциденту та ім'я його власника Bob.

Сценарій 3. Анонімний запит до інциденту Bob.

- Метод: GET.
- Ресурс: 20000000-0000-0000-0000-000000000002.
- Очікуваний результат: HTTP 401 Unauthorized.
- Фактичний результат: HTTP 200 OK.
- Результат: сервер повернув деталі інциденту без автентифікації.

Сценарій 4. Несанкціонована зміна інциденту Bob

### Першопричина

У файлі IncidentQueries.cs метод GetDetailsAsync виконує пошук інциденту за умовою incident.Id == id без перевірки власника або рольових прав користувача.

У файлі IncidentEndpoints.cs метод GetDetailsAsync не містить ресурсної перевірки, а група маршрутів /api/incidents не має вимоги RequireAuthorization().

Унаслідок цього сервер дозволяє читання чужого інциденту за його ідентифікатором, а також анонімний доступ до деталей.

### Стан фіксації

- Вразливість читання: підтверджено HTTP-запитами.
- Вразливість зміни інциденту: підтверджено HTTP 204 та порівнянням стану до і після запиту.
- Vulnerable commit hash: 5ccd296.
- Доказ: результати команд login-and-read.py та curl.exe.


## Виправлення та повторне тестування

Після відтворення IDOR/BOLA було впроваджено серверну перевірку автентифікації, ролі користувача та права доступу до конкретного ресурсу.

Основні зміни:

- IncidentAccessRules.cs — правила доступу для Reporter та Analyst.
- IncidentQueries.cs — фільтрація списку інцидентів за власником та захист внутрішніх коментарів.
- IncidentEndpoints.cs — перевірки доступу для GET, PUT і DELETE.
- UpdateIncidentRequest.cs — захист від overposting за контрактом A-08b.
- IncidentCommentEndpoints.cs — контроль доступу до дочірнього ресурсу.
- IncidentTriageEndpoints.cs — привілейована операція New → Triaged та аудит відмов.
- Program.cs — реєстрація додаткових маршрутів.
- auth-lab.html — браузерна перевірка авторизованих запитів.
- AuthorizationTests.cs — автоматизовані тести контролю доступу.

Вибрано політику HTTP 403 Forbidden для наявного чужого ресурсу. Для неавтентифікованого запиту повертається HTTP 401 Unauthorized, а для неіснуючого ресурсу — HTTP 404 Not Found.

Batch/export — лише якщо є; concurrent transitions — лише якщо викладач надав відтворюваний сценарій; інакше «не застосовується».
