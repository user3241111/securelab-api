## 2. Змінений маршрут

Під час реєстрації клієнт надсилає HTTP-запит до `/api/auth/register`. ASP.NET Core Identity перевіряє облікові дані та створює користувача, пароль якого зберігається в базі даних у вигляді хешу.

Під час входу через `/api/auth/login` Identity перевіряє пароль і створює автентифіковану сесію з використанням cookie. Наступні запити до захищених маршрутів проходять перевірку автентифікації.

Для маршруту `/api/me` дані користувача визначаються на основі автентифікованого контексту. Під час створення інциденту через `POST /api/incidents` сервер отримує власника з `HttpContext.User`, після чого зберігає запис у PostgreSQL та повертає HTTP-відповідь.

Ключові файли:
- `src/SecureLab.Api/Scaffolding/Lab03Identity.cs` — реєстрація, вхід та налаштування автентифікації.
- `src/SecureLab.Api/Scaffolding/Lab02Endpoints.cs` — захищені маршрути інцидентів.
- `src/SecureLab.Api/Data/DatabaseBootstrap.cs` — підготовка початкового стану бази даних.
- `tests/SecureLab.Api.Tests/AuthenticationMechanicsTests.cs` — інтеграційні тести автентифікації та авторизації.

## 3. Виконані зміни

Реалізовано автентифікацію користувачів засобами ASP.NET Core Identity з використанням cookie. Додано реєстрацію, вхід, захищений маршрут `/api/me` та перевірку прав доступу до операцій з інцидентами.

Налаштовано параметри cookie `HttpOnly`, `SameSite=Lax` і `SecurePolicy`. Забезпечено визначення власника інциденту за даними автентифікованого користувача без довіри до переданого клієнтом ідентифікатора.

Перевірено повторюваність початкового стану бази даних після двох послідовних скидань. Додано інтеграційні тести A-01, A-02 та A-05.

## 5. Security-сценарій

**Гіпотеза:** користувач може спробувати створити інцидент від імені іншого користувача, передавши підроблений ідентифікатор власника.

**Стан до перевірки:** API приймає запити на створення інцидентів, тому необхідно перевірити джерело визначення власника.

**Локальний PoC:** автентифікований користувач Bob надсилає `POST /api/incidents` із додатковим полем `ownerUserId`, яке містить ідентифікатор Alice.

**Спостереження:** після створення інциденту його власником залишається Bob.

**Причина захищеної поведінки:** сервер визначає власника за автентифікованим контекстом `HttpContext.User`, а не за полем клієнтського запиту.

**Реалізований захист:** для операції створення інциденту використовується ідентифікатор поточного користувача, отриманий через ASP.NET Core Identity.

**Повторна перевірка:** інтеграційний тест A-05 підтвердив, що підміна власника не відбувається.

**Позитивна регресія:** авторизований користувач може створити інцидент від власного імені, а автоматизовані тести завершуються успішно.

**Залишковий ризик:** cookie-автентифікація потребує додаткового захисту від CSRF. Налаштування `SameSite=Lax` зменшує ризик, але не замінює повноцінний CSRF-захист.
