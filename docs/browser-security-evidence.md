## 2. Stored XSS

**Вразлива версія:** commit `58d1d06`.

У вразливій реалізації дані з `Incident.Description` передавалися до `innerHTML`. Під час відкриття інциденту тестовий XSS-маркер виконувався в браузері.

**Виправлена версія:** commit `8f634cd` (перший коміт із виправленням).

У виправленій реалізації використовується спільна функція `renderSafeText()`, яка вставляє опис інциденту та коментарі через `textContent`.

Результати перевірок:
- XSS-маркер відображається як текст і не виконується.
- Для тестового коментаря не створюються HTML-елементи `img`.
- Апострофи, лапки, HTML-подібні теги та Unicode відображаються без змін.
- Опис максимальної довжини (4000 символів) відображається повністю.

## 3. REG-XSS-01 — регресійна перевірка Stored XSS

**Передумови:** запущений SecureLab API, підготовлена навчальна база даних із тестовими записами, користувач автентифікований.

**Кроки:**

1. Відкрити `http://localhost:5080/browser-lab.html`.
2. Вказати ID тестового інциденту Alice: `20000000-0000-0000-0000-000000000001`.
3. Натиснути кнопку завантаження інциденту.
4. Перевірити відображення опису та коментарів.
5. У DevTools Console перевірити, чи створено HTML-елементи з тестового маркера.

**Очікуваний результат:** XSS-маркер відображається як звичайний текст, JavaScript не виконується, додаткові HTML-елементи не створюються.

**Фактичний результат:** перевірка пройдена.

## 4. CORS

У `Program.cs` налаштована політика `Lab05Cors`.

Дозволений origin: `http://localhost:4173`.

Недозволений origin: `http://localhost:4174`.

Перевірено звичайні GET-запити та preflight OPTIONS із нестандартним заголовком `X-Lab05-Preflight`.

**Дозволений origin:**
- GET повертає HTTP 200 після автентифікації.
- OPTIONS повертає HTTP 204.
- Відповідь містить `Access-Control-Allow-Origin: http://localhost:4173`.
- У Development підтримується `Access-Control-Allow-Credentials: true`.

**Недозволений origin:**
- Браузер блокує доступ до відповіді.
- Відсутній дозвіл `Access-Control-Allow-Origin` для `http://localhost:4174`.

## 5. REG-CORS-01 — регресійна перевірка CORS

**Передумови:** API запущений на `http://localhost:5080`, тестові сторінки доступні на портах 4173 та 4174.

**Кроки:**

1. Запустити тестову сторінку з origin `http://localhost:4173`.
2. Виконати GET і preflight GET через кнопку перевірки.
3. Переглянути GET та OPTIONS у DevTools Network.
4. Повторити перевірку з origin `http://localhost:4174`.
5. Порівняти CORS-заголовки та результати браузера.

**Очікуваний результат:** origin 4173 дозволений, origin 4174 заблокований політикою CORS.

**Фактичний результат:** перевірка пройдена.

## 6. Credentialed CORS

У Development політика CORS дозволяє передавання облікових даних лише для явно вказаного origin `http://localhost:4173`.

Клієнт використовує `credentials: "include"`.

Перевірено:
- Після автентифікації дозволений origin отримує HTTP 200.
- Без автентифікації в режимі інкогніто API повертає HTTP 401.
- У Production, де `AllowCredentials()` не застосовується, браузер блокує credentialed cross-origin запит.

Таким чином, CORS не замінює автентифікацію та авторизацію.

## 7. Content Security Policy

У застосунку використовується CSP:

```text
default-src 'self'; script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'
```

Політика дозволяє завантажувати скрипти, стилі та інші ресурси лише з власного origin, забороняє вбудовування сторінки у фрейми та використання об'єктів.

Для сумісності з CSP JavaScript і CSS сторінки автентифікації винесено в окремі файли.

Після змін перевірено працездатність автентифікації.

## 8. HTTP Security Headers

**X-Content-Type-Options: nosniff** — забороняє браузеру самостійно визначати MIME-тип ресурсу всупереч указаному сервером.

**Referrer-Policy: no-referrer** — забороняє передавання заголовка `Referer` під час переходів і запитів.

**X-Frame-Options: DENY** — забороняє відкривати сторінку всередині iframe.

**CSP frame-ancestors 'none'** — додатково забороняє вбудовування сторінки іншими сайтами.

## 9. Підсумок

У межах лабораторної роботи усунуто перевірений Stored XSS у відображенні описів інцидентів і коментарів, налаштовано обмеження CORS та CSP, перевірено захисні HTTP-заголовки й поведінку запитів з автентифікаційними cookies.

Перевірки `REG-XSS-01` і `REG-CORS-01` документують порядок повторного тестування після змін у застосунку.
